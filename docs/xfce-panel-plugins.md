# Loading xfce4-panel plugins

Documentation of the [xfce4-panel](https://gitlab.xfce.org/xfce/xfce4-panel) plugin
system: how a plugin is built, the exact contract it must honour, and the full
runtime loading flow — including "external" mode via `wrapper-2.0` (Wayland).

Basis analysed: the xfce4-panel source tree (libxfce4panel API 2.0,
`meson.build:13`). Structural note: there is no `src/` directory — the main
binary lives in `panel/`, the public plugin API in `libxfce4panel/`, the plugins
in `plugins/<name>/`.

```
    in <datadir>/xfce4/panel/plugins (+ XDG_DATA_DIRS)
    panel/panel-module-factory.c:173-250
        |
        v
PanelModule (a GTypeModule subtype)      panel/panel-module.c:60, G_DEFINE_FINAL_TYPE :98
  two run modes (enum PanelModuleRunMode):
   INTERNAL: the .so is opened INSIDE the panel process
   EXTERNAL: <helperdir>/xfce4/panel/wrapper-2.0 binary in a subprocess,
             D-Bus communication org.xfce.Panel.Wrapper (/Wrapper/%d)
             common/panel-dbus.h:23-27
```

**Internal vs external decision** (`panel/panel-module.c:346-359`): INTERNAL only
if `X-XFCE-Internal=TRUE` in the `.desktop` **and** an X11 environment, with no
external forcing; otherwise EXTERNAL. Under Wayland (gtk-layer-shell) or with the
`-e` option, everything goes through the wrapper.

GLib API used: `g_module_open / g_module_symbol / g_module_make_resident /
g_module_close` + a sub-class of **GTypeModule** (`panel/panel-module.c:98-108`,
`load=panel_module_load` line 158, `unload=panel_module_unload` line 247).

## 2. Building a plugin (example: clock)

### meson.build — `plugins/clock/meson.build:20-66`
- `shared_module('clock', …)`;
- **`gnu_symbol_visibility: 'hidden'`** (line 29) — only symbols marked
  `G_MODULE_EXPORT` are visible;
- install into `<prefix>/<libdir>/xfce4/panel/plugins` (lines 49-50) → the `.so`
  is named `clock.so`.

### Description file — `plugins/clock/clock.desktop.in.in`
Group `[Xfce Panel]`, `Type=X-XFCE-PanelPlugin`, and the keys that matter:
- **`X-XFCE-Module=clock`** → the `.so` name without extension;
- **`X-XFCE-Internal=TRUE`** → allows running inside the panel process;
- **`X-XFCE-API=@LIBXFCE4PANEL_VERSION_API@`** (= 2.0) — refused if 1.0/Gtk2
  (`panel/panel-module.c:322-329`);
- optional: `X-XFCE-Unique=TRUE`.

### GTypeModule entry point — `plugins/clock/clock.c:221`

```c
XFCE_PANEL_DEFINE_PLUGIN (ClockPlugin, clock_plugin)
```

Macros in `libxfce4panel/xfce-panel-macros.h`:
- `XFCE_PANEL_DEFINE_PLUGIN` (:123-124) → `_XPP_DEFINE_PLUGIN(TypeName, type_name, FALSE, args)`
  (FALSE = non-resident); resident variant: `XFCE_PANEL_DEFINE_PLUGIN_RESIDENT` (:142-143).
- `_XPP_DEFINE_PLUGIN` (:208-235) generates, for each plugin, the **exported
  function**:

```c
G_MODULE_EXPORT GType
xfce_panel_module_init (GTypeModule *type_module, gboolean *make_resident);   /* :213-216 */
```

  It fills `*make_resident`, calls `<name>_plugin_register_type(type_module)` and
  **returns the plugin's GType**.
- `XFCE_PANEL_DEFINE_TYPE` (:165-206) provides `<type_name>_get_type()` and
  `<type_name>_register_type(XfcePanelTypeModule*)` which run
  `g_type_module_register_type(G_TYPE_MODULE(module), XFCE_TYPE_PANEL_PLUGIN, "Xfce"#TypeName, &info, 0)`
  (line 199) — so the real type is named `XfceClockPlugin`.

In the clock example, class_init fills the vtable (`plugins/clock/clock.c:237-245`)
with `construct`, `size_changed`, `mode_changed`, `configure_plugin`.

## 3. The exact plugin contract

Three possible exported functions (probed in order, see §4):

| Function | API | Signature |
|---|---|---|
| `xfce_panel_module_init` | modern (GTypeModule) | `GType (*)(GTypeModule *module, gboolean *make_resident)` — typed in `libxfce4panel/xfce-panel-plugin-provider.h:37-39` (`PluginInitFunc`) |
| `xfce_panel_module_construct` | legacy (4.6 compat) | `XfcePanelPlugin *(*)(const gchar *name, gint unique_id, const gchar *display_name, const gchar *comment, gchar **arguments, GdkScreen *screen)` — `provider.h:31-38` (`PluginConstructFunc`); generated by `XFCE_PANEL_PLUGIN_REGISTER`/`_WITH_CHECK`/`_FULL` (xfce-panel-macros.h:250-361) |
| `xfce_panel_module_preinit` | optional | `gboolean (*)(gint argc, gchar **argv)` — called **before** `gtk_init()`; forbidden to internal plugins (the panel then forces external, `panel/panel-module.c:189-207`) |

The plugin type must be a subtype of **`XFCE_TYPE_PANEL_PLUGIN`**
(`libxfce4panel/xfce-panel-plugin.h:77`), itself a `GtkEventBox` implementing the
GObject interface **`XfcePanelPluginProvider`**.

### `XfcePanelPluginClass` vtable (`xfce-panel-plugin.h:119-157`)

| Callback | Role |
|---|---|
| `void (*construct)(XfcePanelPlugin*)` (h. :126) | "constructs" the OO object, called on realize (once, `libxfce4panel/xfce-panel-plugin.c:1018-1037`, call at :1035) |
| `size_changed` | returns gboolean = handled? |
| `screen_position_changed` (h. :129-130) | panel position/monitor (an `XfceScreenPosition` value) |
| `orientation_changed`, `free_data`, `save`, `about`, `configure_plugin`, `removed` | classic hooks |
| `remote_event(name, GValue) → gboolean` | remote events (notably via D-Bus in external mode) |
| `mode_changed(mode)` (4.10), `nrows_changed(rows)` (4.10), `hidden_event(gboolean)` (4.20.1) | panel state signals |

Type implementation: `libxfce4panel/xfce-panel-plugin.c:245`
(`G_DEFINE_TYPE_WITH_CODE`, parent `GTK_TYPE_EVENT_BOX`, Provider interface via
`xfce_panel_plugin_provider_init` :780-801); signals created in class_init (e.g.
`size-changed` :477, `mode-changed` :370).

**Instance lifecycle**: constructor with the `name`, `unique-id`, `display-name`,
`comment`, `arguments` properties (`xfce-panel-plugin.c:811`) → realize →
`construct()` → state signals emitted by the panel through the Provider vtable →
normal GObject destruction.

## 4. Full flow: config → widget → panel → destruction

**Reading the config** — `panel/panel-application.c:~453-520`: reads `/panels`,
then for each panel `/panels/panel-{id}/plugin-ids` (a gint array, ~line 486) and
the plugin name via `/plugins/plugin-{unique_id}` (`xfce_channel_get_string`,
~line 497). Calls `panel_application_plugin_insert(application, window, name,
unique_id, NULL, -1)` (:500-502).

**Instantiation** — `panel-application.c:833`:
1. `panel_module_factory_new_plugin(factory, name, screen, unique_id, arguments, &new_unique_id)`
   (line 848) → hash lookup by name (`panel-module-factory.c:468`), allocate a
   unique-id if -1 (:472-474), then `panel_module_new_plugin` (:486).
2. **Internal** — `panel/panel-module.c:405`:
   - the `.so` path is derived, not stored: `g_module_build_path(libdir, "X-XFCE-Module")`
     (`panel-module.c:410`) over the plugin directories (build + XDG_DATA_DIRS); the
     factory re-scans on every request to pick up `.so` installs/removals;
   - `g_type_module_use()` (line 426) → triggers `panel_module_load`:
     `g_module_open(filename, G_MODULE_BIND_LOCAL)` (line 180) →
     **symbol probe** `xfce_panel_module_init` (line 210); if absent,
     `xfce_panel_module_construct` (line 221);
   - object creation: OO plugin →
     `g_object_new(module->plugin_type, "name", …, "unique-id", unique_id, …)` (line ~431);
     legacy → direct call of `construct_func` (:444-450);
   - residency: `g_module_make_resident()` if requested (:216-217), **always** for
     internal construct-func plugins (:229).
3. **External** — `panel/panel-module.c:457` →
   `panel_plugin_external_wrapper_new(module, unique_id, arguments)`
   (`panel-plugin-external-wrapper.c:286`): creates a `PanelPluginExternalWrapperX11`
   or `…Wayland` widget. This widget is the **provider** on the panel side; its
   `constructed` exports a D-Bus skeleton on `/org/xfce/Panel/Wrapper/{unique_id}`
   (`panel-plugin-external-wrapper.c:180-203`). On widget realize (spawn line 371):
   `panel_plugin_external_child_spawn` (:501) builds argv — binary
   `<helperdir>/wrapper-<api>` = **`wrapper-2.0`** (`WRAPPER_BIN` + api,
   `panel-plugin-external-wrapper.c:44`) with
   `[FILENAME .so, UNIQUE_ID, SOCKET_ID, NAME, DISPLAY_NAME, COMMENT, ARGS…]` (enum
   `PLUGIN_ARGV_*`, `libxfce4panel/xfce-panel-plugin-provider.h:146-156`). Under X11,
   `SOCKET_ID = gtk_socket_get_id()` of a `GtkSocket` (`panel-plugin-external-wrapper-x11.c:130`);
   spawn via `g_spawn_async(… G_SPAWN_DO_NOT_REAP_CHILD …)` and `g_child_watch_add_full`
   (`panel-plugin-external.c:604`). **Crash → automatic restart** with a counter/dialog
   box (:452-495, :753).
4. **Adding to the panel** — `panel-application.c:853-873`: connects the
   `provider-signal` signal, inserts into the box via `panel_itembar_insert`
   (~line 866), then `panel_window_set_provider_info(window, provider, FALSE)`
   (:872) which pushes size/orientation
   (`panel-window.c:4131-4137 → xfce_panel_plugin_provider_set_size`). For external
   plugins, these properties travel through the `Set` D-Bus signal (tuples `(uv)`
   type+value, `panel-plugin-external-wrapper.c:295-347`).

**Destruction** — the `PROVIDER_SIGNAL_REMOVE_PLUGIN` signal
(`panel-application.c:~779-800`): `xfce_panel_plugin_provider_removed(provider)`
(the plugin's hook) → `gtk_container_remove(itembar, provider)` → removal of the
xfconf config + saving of the ids. GObject consequences: the weak-ref
`panel_module_plugin_destroyed` (`panel/panel-module.c:280-301`) decrements the
use_count and calls `g_type_module_unuse()` if internal (→ `g_module_close`,
lines 247-265); the factory removes the object from its list via a weak-ref. For a
wrapper: unrealizing the external widget sends the `ACTION_QUIT` D-Bus action to
the subprocess (`panel-plugin-external.c:385-402`).

## 5. Role of the `wrapper/` directory

The directory builds **a standalone `wrapper-2.0` executable** installed into
`<helperdir>/xfce4/panel` (`wrapper/meson.build`). It is not a test tool: it is
the **runtime container for external plugins**, used by default under Wayland and
for any plugin that is not `X-XFCE-Internal`.

- **`wrapper/main.c` (394 lines)** — parses argv (:267-273), renames the process
  (`prctl PR_SET_NAME "panel-{id}-{name}"`, :279), **`g_module_open(filename,
  G_MODULE_BIND_LOCAL)` line 284**, calls `xfce_panel_module_preinit` if present
  **before** `gtk_init()` (:292-299 — hence the external-only constraint on the
  panel side), `gtk_init` :301, creates a D-Bus proxy to the panel on
  `/org/xfce/Panel/Wrapper/{unique_id}` (interface `org.xfce.Panel.Wrapper`,
  :305-321; silent quit if the panel disappears, :44-56), then
  `wrapper_module_new(library)` + `wrapper_module_new_provider(…)` (:326-337) and
  **`wrapper_plug_new(socket_id, unique_id, proxy)`** (:338). The provider
  (GtkWidget) is embedded in the plug (`gtk_container_add`, :345), the D-Bus
  `Set`/`RemoteEvent` signals are wired to the Provider API. `gtk_main()` loop
  :362.
- **`wrapper/wrapper-module.c` (166 lines)** — the **WrapperModule** class, a
  GTypeModule subtype whose `load`/`unload` are empty (load :90-92, unload :98+,
  the `.so` is already opened by main.c). `wrapper_module_new_provider`
  (~:119-166) reproduces the panel's logic: `g_type_module_use`, symbol
  `xfce_panel_module_init` → `g_object_new(plugin_type, …)`; else symbol
  `xfce_panel_module_construct`. **The same two exported functions as loading by
  the main panel — but separate code** (no reuse of PanelModule).
- **`wrapper-plug.h/.c`** — the `WrapperPlug` GObject interface on `GtkWindow`, 2
  implementations:
  - **X11**: `WrapperPlugX11`, a subclass of **`GtkPlug`** (`wrapper-plug-x11.c:54`)
    — embeds into the panel's `GtkSocket` (ID passed via argv);
  - **Wayland**: `WrapperPlugWayland`, a subclass of **`GtkWindow`** +
    gtk-layer-shell (`wrapper-plug-wayland.c:63`) — a floating window positioned
    geometrically, driven by the `SET_MONITOR`/`SET_GEOMETRY` D-Bus props.

On the panel side, the mirror class is `PanelPluginExternalWrapper` (+ x11/wayland
subclasses) in `panel/panel-plugin-external-wrapper*.c`, which acts as the local
"provider" and relays D-Bus ↔ Provider API.

## 6. What differs from "just exporting a function"

1. **GTypeModule, not just a symbol**: the panel sub-classes `GTypeModule`
   (PanelModule); opening the `.so` is encapsulated in `load`, the load reference
   managed by `g_type_module_use/unuse` (`panel-module.c:429,300`). GObject types
   are **registered/unregistered** via `g_type_module_register_type` during the
   use: a plugin can be reloaded after removal.
2. **Explicit residency**: `make_resident` returned by `xfce_panel_module_init` →
   `g_module_make_resident` (`panel-module.c:214`) — non-resident plugins can be
   `g_module_close()`d (memory freed).
3. **Hidden symbol visibility** when building the `.so`
   (`plugins/clock/meson.build:27`): only
   `xfce_panel_module_init` / `_construct` / `_preinit` (marked `G_MODULE_EXPORT`)
   are reachable.
4. **Metadata via `.desktop`**: the `.so` name, the required API,
   internal/external, uniqueness — all come from
   `<datadir>/xfce4/panel/plugins/<name>.desktop`, not from the `.so` nor panelrc.
5. **No absolute path in the config**: panelrc holds only the NAME + unique-id;
   the path is derived and the factory re-scans on every request.
6. **Two ABIs** (modern GTypeModule init / legacy construct) + preinit, chosen at
   runtime by symbol probing (`panel-module.c:190-233`).
7. **GObject Provider interface** (`XfcePanelPluginProvider`, provider.h:40-75):
   the panel never talks to the widget object directly but through this interface
   — which makes the internal case (direct vtable, e.g. `xfce-panel-plugin.c:1450`)
   and the external case (same functions serialized into `Set`/`RemoteEvent` D-Bus
   signals) transparent.

## 7. Reload: why an `install` crashes the panel

The save path of a panel that is exiting (`main.c` → `g_object_unref(application)`
→ `panel_application_save` → `panel_application_save_window`,
`panel-application.c:1350`) calls `xfce_panel_plugin_save` →
`g_signal_emit(plugin, SAVE)`, i.e. **a jump into the plugin's code**. If the
loaded `.so` was rewritten in the meantime, that jump lands in an image that is no
longer its own.

- `X-XFCE-Internal=TRUE` ⇒ the plugin runs **inside** the panel process, opened
  with `G_MODULE_BIND_LOCAL` and made resident (`g_module_make_resident`,
  `panel-module.c:214`): the file stays **mapped in execution** for the panel's
  lifetime. Linux does not prevent writing a `.so` mapped by `dlopen` (ETXTBSY
  only protects the main binary's text).
- `cp` writes **through the same inode**: the code pages the panel runs become
  those of another binary. The next call into the plugin (the restart's `save`) →
  SIGSEGV, `ip` = an absurd offset or `0x0`, backtrace `signal_emit_unlocked_R` ←
  `panel_application_save_window` ← `panel_application_finalize`.
- `cp` to `file.new` + `rename(2)`: the old inode stays mapped (opens-then-unlink),
  the next reload picks up the new file. This is what `just install` does.

Measurement (`tools/panel-repro.sh`, demo + hello loaded, panel stopped via
`xfce4-panel -q`): `OVERWRITE=cp` → 3/3 `panel_exit=139`, log cut on the panel's
save line; `OVERWRITE=rename` → 3/3 `panel_exit=0`, `save` + `free_data` executed
and config saved.

A separate point, independent of our code: `xfce4-panel -r` is a **restart race**
— the exiting panel relaunches `argv[0]`, the new instance finds
`org.xfce.Panel` still owned, prints "there is already a running panel" and stops:
**no** panel is left (reproduced 5/5 without any Rust plugin). Prefer
`xfce4-panel -q` then relaunch.
