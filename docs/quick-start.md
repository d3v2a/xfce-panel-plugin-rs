# Quick start: a minimal xfce4-panel plugin in Rust

The smallest plugin that satisfies the panel's contract: one label, no
settings, no xfconf. Build it, install it, see it in the bar — then extend it.

## 1. System libraries

`crates/xfce-panel-sys/build.rs` probes `libxfce4panel-2.0` and
`libxfce4util-1.0` with `pkg-config`; the `xfconf` crate (0.3, xfce4-rs) probes
`xfconf-1.0` through `system-deps`, and `gtk` probes `gtk+-3.0`. The `xfconf`
line is only needed by a plugin that turns on the `settings` feature (see
[Features](../readme.md#features)). Install the `-dev` / `-devel` packages of
your distro:

| pkg-config name | Debian / Ubuntu | Fedora | Arch |
|---|---|---|---|
| `gtk+-3.0` | `libgtk-3-dev` | `gtk3-devel` | `gtk3` |
| `libxfce4panel-2.0` | `libxfce4panel-2.0-dev` | `xfce4-panel-devel` | `libxfce4panel` |
| `libxfce4util-1.0` | `libxfce4util-dev` | `libxfce4util-devel` | `libxfce4util` |
| `xfconf-1.0` | `libxfconf-0-dev` | `xfconf-devel` | `xfconf` (settings only) |

Plus Rust **1.95+** (edition 2024) and `pkg-config`. A probe that fails prints
a `cargo::warning` naming the missing package — the build needs the `.pc` files,
not just the libraries.

## 2. The code

`crates/xfce-panel-hello/src/lib.rs`, in full:

```rust
use xfce_panel::gtk::prelude::WidgetExt;
use xfce_panel::{PanelPlugin, Plugin, gtk};

#[derive(Default)]
pub struct Hello;

impl PanelPlugin for Hello {
    const TYPE_NAME: &'static str = "XfceRustHello";
    type State = ();

    fn construct(_state: &mut Self::State, plugin: &Plugin) {
        let label = gtk::Label::new(Some("Hello from Rust"));
        label.set_widget_name("xfce-panel-rs-label");
        plugin.add_widget(&label);
        label.show();
    }

    fn size_changed(_state: &mut Self::State, plugin: &Plugin, size: i32) -> bool {
        plugin.set_size_request(size, size);
        true
    }
}

// Resident: the `.so` registers a `GType`, so it must never be `dlclose`d.
xfce_panel::define_panel_plugin!(Hello);
```

What each piece is for:

- **`TYPE_NAME`** — the `GType` name the plugin registers with the panel's
  `GTypeModule`. It must be unique among loaded plugins.
- **`type State = ()`** — per-instance state, dropped at `free_data`. `()` when
  there is nothing to keep; the demo uses a struct holding its xfconf channel.
- **`construct`** — called **once, at the plugin's realize**
  (`xfce-panel-plugin.c:1018-1037`). The plugin *is* a `GtkEventBox` with
  `visible-window = FALSE`, a `GtkBin`: it takes exactly one child (a `GtkBox`
  in practice).
- **`size_changed`** — return `TRUE` = "I handled my size"; `FALSE` makes the
  panel force a square `set_size_request` (`xfce-panel-plugin.c:1448-1455`).
  `size == -1` means "automatic".
- **`define_panel_plugin!(Hello)`** — exports the single C entry point the
  panel `dlsym`s, `xfce_panel_module_init`: it registers the type with the
  panel's module and returns its `GType`. The `true` asks for residency —
  **required** as soon as the plugin registers `glib` types, since `dlclose`-ing
  the library that owns a registered type breaks the panel.

The `XfcePanelPluginClass` vtable has ~13 slots; the framework installs a
trampoline for each and the trait gives them default bodies, so a plugin
implements only what it uses (`construct` and `size_changed` here). Every
callback is panic-guarded: a `panic!` in plugin code cannot unwind into the
panel process.

## 3. Build

```sh
cargo build --release
```

Produces `target/release/libhello.so` (the `cdylib`), plus the plugin's
`.desktop` under `target/release/build/*/out/hello.desktop` — generated by the
crate's `build.rs` via `xfce_panel::build::write_desktop`
(`X-XFCE-API=2.0`, `X-XFCE-Internal=TRUE`). Never write that file by hand.

Sanity checks before touching a running panel:

```sh
just test            # unit tests (no panel needed)
just test-abi        # dlopen the cdylib, call xfce_panel_module_init, check the
                     # returned GType descends from XfcePanelPlugin
```

`just test-abi` matters: the panel performs **no type check** on the returned
`GType`, so a wrong parent is a silent segfault of the panel, not of the plugin.

## 4. Install and run

Panel 4.19.4+ scans the XDG data directories, so a per-user install is enough:

```sh
just install         # → ~/.local/lib/xfce4/panel/plugins/libhello.so
                     # → ~/.local/share/xfce4/panel/plugins/hello.desktop
just refresh         # xfce4-panel -q, then relaunch
```

`just install` copies to `file.new` then swaps with `rename(2)`: a running panel
has the previous `.so` mapped and resident, and overwriting that inode in place
rewrites the code pages it is executing (next call in → SIGSEGV). See *Reload
safety* in the root README; `tools/panel-repro.sh` measures it.

Then **Panel → Panel preferences → Add new items → Rust Hello**.
`just debug` restarts with `PANEL_DEBUG=module-factory,main` if the plugin does
not show up: the log says whether the `.desktop` was scanned and the `.so`
loaded.

## 5. From here

Add settings, a dialog, and rendering: turn on the `settings` feature
(`xfce-panel = { version = "0.1", features = ["settings"] }`), which is what
`crates/xfce-panel-demo` does; it is the same shape plus
[`#[xfce_panel::panel_settings]`](plugin-demo.md) and a preferences dialog bound
straight to xfconf. The internals behind each step:

- [xfce-panel-plugins.md](xfce-panel-plugins.md) — the exact contract, the
  `.desktop` keys, the full load → widget → destruction flow, external mode.
- [audit-ffi-rust.md](audit-ffi-rust.md) — the vtable member by member,
  the C types, why the `GType` registration is manual.
